# Trend Score v3 — 명세

이 문서는 점수와 상태가 **무엇을 의미해야 하는지**를 먼저 정하고, 구현이 그 의미를 지키는지 확인하는
기준으로 쓴다. 구현은 `packages/scoring/src/index.ts`(축 상한·상태 규칙)와
`packages/pipeline/src/initial-score.ts`(축 계산)에 있다. 수치 근거는 두 파일의 주석과
`docs/handoff-2026-08-26.md` 4절에 있다.

## 1. 점수가 의미하는 것

**"이 서비스가 지금 얼마나 주목받고 있는가"를 0~100으로 나타낸 순위용 숫자.** 절대적 인기가 아니라
최근 반응이다. 같은 반응이라도 오래되면 값이 줄어야 하고(반감기 7일), 채널이 달라도 같은 위치의
반응이면 같은 값을 받아야 한다(채널 내 백분위).

점수는 두 부류의 축으로 이뤄진다.

| 부류 | 축 | 상한 | 뜻 |
|---|---|---|---|
| 반응 신호 | `velocity` | 40 | 채널 내 반응 크기 백분위(HN points · PH votes · Reddit upvotes · GitHub stars). 제곱 곡선으로 꼬리 강조 |
| 반응 신호 | `comments` | 20 | 채널 내 토론 깊이 백분위(댓글 수, GitHub 은 이슈 수) |
| 반응 신호 | `crossSource` | 20 | 추가 채널 하나당 20/3. 채널별 가장 신선한 언급의 감쇠를 무게로 씀 |
| 맥락 | `novelty` | 15 | 첫 발견 후 경과: ≤24h 15 · ≤7d 11.3 · ≤30d 5.6 · 그 외 1.9 |
| 맥락 | `quality` | 5 | 설명 길이 ≥80자 5 · ≥20자 4 · 그 외 3. 동점 정리용 |
| (0) | `productGrowth` `threads` `reddit` `instagram` | 0 | 축·컬럼은 유지. GitHub 스타는 velocity 로 흡수, 나머지는 채널 미가동 |

반응 신호 세 축에는 **반감기 7일 감쇠**가 걸린다(`recencyDecay`). 감쇠는 후보별로 축 점수를 만든 뒤
곱하고 최대값을 취한다 — 백분위는 상대 순위라 원시값을 감쇠하면 아무것도 바뀌지 않기 때문이다.
재수집되면 `collected_at` 이 갱신되어 감쇠가 풀린다. 즉 **"HN·PH 첫 화면에 계속 있는가"가 유지 조건**이다.

### 반응 신호(engagementSignal)

`velocity + comments + crossSource` (각 상한 적용). 상태 판정과 순위 노출 하한은 총점이 아니라 이 값을 본다.
맥락 축은 "지금 반응이 있는가"와 무관하므로 판정에서 뺀다.

## 2. 순위에 나오는 조건

`engagementSignal >= 0.5` (`RANKING_SIGNAL_FLOOR`). 미달이면 `trend_scores.ranked = false`.

- 순위표에서만 빠진다. 검색·카테고리·상세·sitemap·워치리스트에는 그대로 나온다. 삭제·숨김 아님.
- 순위 번호는 `—` 로 표시하고 툴팁으로 이유를 설명한다.
- 재수집으로 반응이 붙으면 다음 채점에서 자동 복귀한다.

근거: 반응 신호가 0인 항목은 서로 구분할 근거가 없어 순위가 임의 순서가 된다(2026-08-25 실측, 793건 중
459건이 20건 이상 동점 그룹). 하한 0.5 는 그 동점을 완전히 없애면서 가장 적게 빼는 값이었다.

## 3. 상태가 의미하는 것

상태는 **반응 신호의 하루 변화**로만 판정한다(`calculateStatus`). 총점이나 절대 수준으로 판정하지 않는다.
`Δ = 오늘 signal − 직전(같은 척도) signal`.

| 상태 | 조건 (위에서부터 첫 일치) | 뜻 |
|---|---|---|
| `NEW` | 첫 발견 ≤ 24h | 오늘 처음 발견. 이력 없어도 판정 가능 |
| `WATCH` | 같은 척도의 직전 스냅샷 없음 | 아직 움직임을 말할 수 없음 |
| `REVIVAL` | 발견 > 7일 · 직전 signal < 3 · Δ ≥ +3 | 조용했던 서비스가 다시 반응을 얻음 |
| `SURGING` | Δ ≥ +10 | 하루 만에 순위권 진입 수준의 반응 증가 |
| `PEAK` | signal ≥ 40 · \|Δ\| < 1.5 | 상위 1% 에서 반응이 유지됨(재수집이 이어짐) |
| `RISING` | Δ ≥ +3 | 반응이 눈에 띄게 늘었음 |
| `FALLING` | Δ ≤ −3 | 반응이 줄고 있음. 감쇠만으로는 상위권(S ≥ 32)만 도달 |
| `STABLE` | 나머지 | |

### 붙으면 안 되는 경우 (반례)

- 반응이 그대로인데 발견 7일째·30일째라서 `FALLING` — **안 된다.** novelty 계단은 signal 에 없다.
- 점수가 높다는 이유만으로 `SURGING` — **안 된다.** 변화가 없으면 급등이 아니다. 유지되면 `PEAK`.
- 설명이 채워져서 `RISING` — **안 된다.** quality 는 signal 에 없다.
- 갓 발견된 서비스가 첫날 `WATCH` — **안 된다.** `NEW` 를 먼저 본다.
- 점수 척도가 바뀐 날 전 엔티티가 `RISING`/`FALLING` — **안 된다.** 이력은 같은 `scoring_version` 끼리만 비교한다.

### 임계값 근거

2026-08-26~09-01 저장 스냅샷 5,246건의 하루 전이를 v3 척도로 환산:

```
signal Δ 분포     중앙 -0.13 · 95% 0.00 · 99% +1.33 · 최대 +46.4
Δ ≥ +3  6.3/일    Δ ≥ +10  2.8/일    Δ ≤ -3  11/일    Δ ≤ -4  3.8/일
감쇠만의 하루 하락  S=30 → -2.8 · S=40 → -3.8
signal 분포        최고 54 · 상위1% 40 · 상위5% 21.5 · 중앙 0.9
```

상승은 재수집으로 지표가 실제로 늘 때만 나오므로 하락보다 드물다. 이것은 데이터의 성질이며 임계값을
낮춰 상승을 만들어내지 않는다.

## 4. 척도를 바꿀 때 지켜야 하는 순서

1. `SCORING_VERSION` 을 올린다. 올리지 않으면 웹·파이프라인이 옛 척도와 비교해 전 엔티티가 뒤집힌다.
2. `pnpm --filter @ai-trend-radar/pipeline exec tsx src/cli/simulate-decay.ts` 로 상태 분포를 본다(DB 쓰기 없음).
3. 배포 후 `backfill-score-history.ts --date=<직전 날짜> --write` 로 직전 스냅샷을 새 척도로 채운다.
   안 하면 하루 동안 전 엔티티가 `WATCH` 로 보인다.
4. 다음 날 `/admin/ops` 의 "오늘 점수 분포" 또는 `verify:live` 출력으로 분포를 확인한다.
5. **하루치가 아니라 일주일치**로 다시 본다. 달력 축(novelty 계단)처럼 정상 상태에서만 드러나는 문제가 있다.

## 5. 알려진 한계

- 같은 채널 안의 반복 언급은 가산되지 않는다(후보별 최대값). "여러 번 화제가 됨"은 잡지 못한다.
- 채널 표본이 10개 미만이면 백분위 분모를 n 으로 둬 1위가 상한에 못 닿는다(보수적 처리). Reddit 이
  소량으로 복구되면 초기에 낮게 평가된다.
- 백필은 `collected_at ≤ 기준시각` 으로 재구성하므로, 그 뒤 재수집된 항목은 재구성에서 빠져 첫날 `WATCH`
  로 남을 수 있다.
- GitHub 채널은 원본 35~50건으로 표본이 작아 스타 백분위가 거칠다.
