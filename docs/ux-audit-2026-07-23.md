## A. 총괄 진단

### 현재 서비스 완성도
**약 70% — "공개 베타" 수준.** 파이프라인(수집→점수화→AI 분석→공개)과 페이지 골격, SEO 인프라, PWA, 신뢰 장치(방법론·FAQ·AI 주의 문구)는 실제 서비스급으로 갖춰져 있다. 반면 **데이터 표면 품질(서비스명·카테고리·순위 정합성·출처 메타)**과 **상태 설계(로딩/에러/피드백)**, **성능(TTFB 2~3초)**이 "출시 직전" 기준에 못 미친다.

### 가장 잘된 점
1. **신뢰 설계의 기본기**: 방법론 페이지, "AI 분석은 참고 정보" 고지, 신뢰도 점수, FAQ — 트렌드 인텔리전스 서비스의 핵심인 "이 순위를 왜 믿어야 하나"에 답하려는 구조가 존재한다.
2. **기술 인프라**: JSON-LD(홈/상세/방법론), 동적 OG 이미지, sitemap/robots/llms.txt, PWA 매니페스트, RLS 기반 데이터 접근, URL 파라미터 기반 비교 상태(새로고침/뒤로가기 안전).
3. **모바일 기초**: 360px에서 가로 오버플로 0, 테이블→카드 전환, safe-area 대응, 하단 탭+더보기 시트.

### 가장 큰 문제
**"신뢰를 파는 서비스인데 데이터 표면이 신뢰를 깎는다."**
- 탐색 페이지에서 순위 번호가 34→33→35처럼 역전되어 보임(동점 정렬 버그, 6곳 확인).
- 서비스명이 "I ran 12 AI bots predicting stocks…" 같은 HN 원문 제목 그대로.
- 상세 페이지 출처 영역에 "5분 전 수집", "광고 의심 낮음" 등 **실데이터가 아닌 고정 문구**가 사실처럼 노출.
- 첫 화면 KPI가 "상승 중인 서비스 0", "교차 채널 확산 0"을 그대로 노출 — 서비스의 가치 제안("확산 속도", "교차 신호")이 스스로 0이라고 말하는 셈.

### 출시 가능 여부
**조건부 가능.** 지금 상태로도 "베타" 라벨을 달면 공개 운영 가능. 단, Phase 1(아래) 항목 — 순위 정렬 버그, 가짜 출처 메타, dead UI, 에러 바운더리 — 을 해결하기 전에는 "정식 출시"라고 부르기 어렵다.

### 현재 서비스가 주는 인상
"진지하게 만든 데이터 프로덕트인데, 아직 데이터가 어리다." 화면 구조와 문구는 전문적이지만, 목록을 30초만 스크롤하면 원문 제목 서비스명·전부 동일한 '관찰 대상' 상태·역전된 순위가 눈에 들어와 초기 신뢰가 꺾인다.

### 핵심 개선 방향 3가지
1. **데이터 표면 신뢰 회복**: 정렬 버그 수정, 가짜 출처 메타 제거/실데이터화, 서비스명 정제(LLM 단계에서 표시명 추출), 0짜리 KPI의 조건부 표현.
2. **상태 설계 완성**: loading.tsx/error.tsx 전면 도입, 폼 제출 pending/성공 피드백, dead UI 제거.
3. **성능·일관성 기반 다지기**: force-dynamic→revalidate 캐싱 전환, explore 이중 렌더 해소, 디자인 토큰 준수율 회복(.card/.input 공통 클래스).

## E. 화면별 상세 분석

### 홈 (오늘의 레이더, `/`)
- **역할**: 30초 안에 "오늘 무엇이 뜨는가"와 서비스 신뢰 근거를 전달하는 랜딩.
- **잘된 점**: h1 단일·명확, KPI→Top3 히어로→랭킹→FAQ의 정보 위계가 논리적. FAQ가 신뢰 질문("믿어도 되나요")에 선제 대응. CollectionPage+FAQPage JSON-LD.
- **문제점**: ① dead 필터 버튼 2개(I-03) ② KPI 0 노출(I-11) ③ 1위 카드 제목이 원문 문장(I-09) ④ "MVP 데이터 안내" 문구가 정식 서비스 톤과 충돌 ⑤ 로딩 상태 없음(TTFB 2.7초 동안 백지).
- **사용자 영향**: 첫 화면에서 신뢰 형성과 파손이 동시에 일어남.
- **개선 방향**: dead 버튼→탐색 링크화, KPI 조건부 렌더, 스켈레톤 도입, "MVP 안내"는 베타 배지로 승격하거나 제거.
- **우선순위**: High

### 트렌드 탐색 (`/explore`)
- **역할**: 필터·검색으로 전체 풀을 탐색하는 파워유저 화면.
- **잘된 점**: 검색+5필터 서버사이드 처리, URL 공유 가능, 빈 상태 문구·초기화 링크 제공, 모바일 카드 전환.
- **문제점**: ① 순위 역전(I-01) ② 채널 dead 옵션(I-04) ③ 88건 무페이지네이션 — 모바일 7,559px(I-18) ④ 이중 렌더 655KB(I-08) ⑤ '상태' 열이 전부 동일 값이라 정보량 0.
- **개선 방향**: comparator 통일, 20건 페이지네이션(뉴스 페이지 패턴 재사용), 상태 열은 다양화 전까지 숨기고 '24H 변화'를 강조.
- **우선순위**: Critical(정렬)/High(나머지)

### 서비스 상세 (`/services/[slug]`)
- **역할**: "이 서비스가 왜 뜨는지"를 근거와 함께 설득하는 핵심 전환 화면.
- **잘된 점**: 정보 설계 우수 — 왜 뜨나/기간 차트/플랫폼 지표/호오 반응/추천 대상/활용 사례/국내 기회. SoftwareApplication JSON-LD, 동적 OG 이미지, AI 주의 고지.
- **문제점**: ① 출처 메타 가짜 문구(I-02) — 이 화면 최대 리스크 ② 상세 진입 시 전체 88건 로드+순차 쿼리(I-23) ③ "왜 지금 뜨고 있나요?" 본문 첫 문단이 상단 설명과 동일 문장 중복 ④ 기간 차트가 스냅샷 2개면 사실상 직선(정직하지만 안내 문구는 좋음 — 유지).
- **개선 방향**: 출처 실데이터화, 중복 문단 제거(요약과 근거 리스트 분리), 쿼리 최적화.
- **우선순위**: Critical(출처)/Medium(나머지)

### 카테고리 (`/categories`)
- **잘된 점**: 카드→탐색 필터 연결 자연스러움.
- **문제점**: "상승 0"이 전 카드 반복(I-11의 변주). 카테고리가 7개뿐이고 '기타' 18개로 2위 규모 — 분류 체계가 데이터를 못 따라감(I-10).
- **개선 방향**: 상승 0일 때 해당 지표 숨김, '기타' 축소를 위한 분류 보강.
- **우선순위**: Medium

### 서비스 비교 (`/compare`)
- **잘된 점**: URL 상태(새로고침 안전), 최대 4개 제한 명확, 빈 상태 안내.
- **문제점**: ① 진입점이 이 페이지뿐(I-29) — 목록/상세에서 "비교에 담기" 불가라 기능 발견성이 낮음 ② 사이드바 메뉴에는 있으나 모바일에서는 더보기 시트 안(의도된 결정) ③ sitemap 누락(I-19).
- **우선순위**: Medium

### AI 뉴스 (`/news`)
- **잘된 점**: 이 서비스에서 상태 설계가 가장 완성된 화면 — 검색어 인지형 빈 상태, TODAY 배지, 반응형 페이지네이션(PC 넘버링/모바일 이전·다음), 원문 링크 명확. **이 패턴을 타 화면의 표준으로 삼을 것.**
- **문제점**: ① 출처 편중(I-31) ② sitemap 누락(I-19) ③ NewsArticle JSON-LD 없음(I-20).
- **우선순위**: Low

### 리포트 (`/reports`, `/reports/[date]`)
- **잘된 점**: 날짜 검증→noindex/404 처리 correct, 빈 상태 존재.
- **문제점**: 카드 제목이 heading이 아닌 strong(문서 구조), 목록이 2건뿐이라 허전 — 리포트 가치(요약 3줄 등) 미리보기 부재. Article JSON-LD 없음.
- **우선순위**: Low

### 로그인 (`/login`)
- **잘된 점**: 가치 제안 문구, 최소 권한 고지("기본 프로필과 이메일만"), "로그인 없이 둘러보기", 로딩/에러 상태 구현(role=alert), noindex.
- **문제점**: 없음에 가까움. 유지.
- **우선순위**: Low

### 관심 목록 (`/watchlist`) — 로그인 후 실조작은 추가 확인 필요
- **잘된 점**: 비로그인 시 inline 안내(문맥 유지 — 이 방식을 표준으로 권장), 폴더/메모 구조, useActionState 인라인 에러.
- **문제점**: ① 비어있지 않은 폴더 삭제 시 throw 크래시 경로(I-25) ② 저장 성공 피드백 부재(I-12).
- **우선순위**: Medium

### 설정 (`/settings`) — 로그인 후 실조작은 추가 확인 필요
- **문제점**: ① 저장 성공 피드백 없음(I-12) ② 계정 삭제가 체크박스 1개로 즉시 영구 삭제(I-24) ③ 알림·다이제스트 설정 UI는 있으나 실제 발송 파이프라인 존재 여부 추가 확인 필요 — 미발송이면 설정 자체가 dead UI.
- **우선순위**: High(삭제 안전장치)

### 관리자 (`/admin/review`, `/admin/ops`) — 프로덕션 시각 확인은 추가 확인 필요
- **잘된 점**: 권한 게이팅 정확(비로그인→로그인, 비관리자→홈), 승인 버튼이 분석 준비 전 disabled, 검색어 인지형 빈 상태.

- **문제점**: 경미 — 404에 검색창 제공하면 더 좋음.
- **우선순위**: Low

## F. 개선된 사용자 흐름

### 신규 방문자
- **현재**: 홈 진입(2.7초 백지) → KPI에서 "상승 0" 목격 → Top3 카드(1위가 영문 문장 제목) → 랭킹 → 상세 → 관심 등록 클릭 → 로그인 페이지.
- **혼란 지점**: 로딩 백지, 0 KPI, dead 필터 버튼, 원문 제목.
- **개선 후**: 홈 진입(스켈레톤 즉시 표시) → 유효한 KPI만 노출 → 정제된 한국어 서비스명 Top3 → 상세(실출처 근거) → 관심 등록 → 로그인 → **돌아와서 저장 확인 토스트 + "관심 목록 보기" 안내**.

### 재방문 사용자
- **현재**: 홈 재진입 → 어제와 무엇이 달라졌는지 표시 없음(rankChange 항상 "—") → 관심 목록 수동 확인.
- **개선 후**: 순위 변동(▲▼) 실데이터화 → 관심 서비스의 점수 변화 하이라이트 → (Phase 3) 일간 다이제스트 발송으로 재방문 트리거.

### 모바일 사용자
- **현재**: 하단 탭 4+더보기, 탐색은 7,500px 스크롤, 일부 터치 타깃 19~39px.
- **개선 후**: 탐색 페이지네이션, 터치 타깃 44px, 필터는 접힘형(모바일에서 5개 드롭다운 상시 노출 → "필터" 버튼으로 축약) 검토.

## G. 디자인 시스템 개선안

현행 토큰(색 33종·그림자 3·radius 4·모션 3)은 유지하되, **준수율 회복 + 결손 토큰 보충**이 골자. 전면 교체 불필요.

- **컬러**: 신규 토큰 3개 추가 — `--danger-text: #b42318`(현재 7회 하드코딩), `--brand-border-soft: #ded9ff`(5회), `--shadow-focus: 0 0 0 3px rgb(109 93 251 / 10%)`(4회). 이후 하드코딩 hex 24건 치환.
- **타이포**: 27종 → 8단계로 수렴: Display 34 / H1 28 / H2 21 / H3 17 / Body 14 / Body-sm 13 / Caption 12 / Micro 11. 12.5px·13.5px 등 소수점 크기 제거. font-weight는 400/500/650/800 4단계로.
- **간격**: 4px 그리드 — 4/8/12/16/20/24/32/48. 홀수 gap(3,5,7,9,11) 정리.
- **Radius**: 실사용 최빈값에 맞춰 토큰 재정의 — sm 8 / **md 10**(현 9·10·11px 통합) / lg 16 / pill 999. 코드가 토큰을 따라오게 하지 말고 토큰이 현실을 인정하게 조정.
- **레이아웃**: 브레이크포인트 3종으로 통일 — 767(모바일)/1180(태블릿·축약 사이드바)/1360(와이드). 767px 4개 블록 통합. z-index 토큰화: base 1 / sticky 10 / header 20 / fab 25 / nav 30 / overlay 40 / toast 50.
- **버튼**: Primary/Secondary/Danger 유지 + 상태 보강 — `:active`(--brand-primary-active 활용, 현재 미사용), `:focus-visible` 링, `[data-loading]` 스피너. Danger radius 10px→토큰 통일.
- **폼**: 공통 `.input` 클래스 신설(현재 6곳 중복 정의, 높이 39/40/42px 혼재 → 42px 통일). outline:0 제거하고 `--shadow-focus` 적용.

## I. 최종 권고안

- **판단: 현재 디자인 유지 + 부분 개선.** 전면 재설계 불필요. 정보 설계와 시각 언어의 뼈대는 목적에 부합하며, 문제는 구조가 아니라 **표면 데이터 품질·상태 설계·토큰 규율**이라는 마감 층위에 있다.
- **근거**: 화면 골격(홈 위계, 상세 정보 설계, 뉴스 페이지 완성도)과 인프라(SEO/PWA/RLS/파이프라인)는 재사용 가치가 높고, 발견된 Critical 2건 모두 국소 수정으로 해결된다.
- **가장 먼저 시작할 작업**: I-01 순위 정렬 버그(반나절, 신뢰 직결) → I-02 가짜 출처 문구 제거(반나절) → I-03/04 dead UI 제거.
- **추가 기능 개발보다 먼저 해결할 것**: 새 기능 0건 추가 상태로 Phase 1+2를 끝내는 것. 특히 ① 데이터 표면 신뢰(정렬·출처·서비스명), ② 로딩/에러/피드백 상태, ③ 성능 캐싱. 이 세 가지가 미해결인 채 기능을 늘리면 모든 신규 화면이 같은 부채를 상속한다.
- **관점 충돌 조정**: 개발 관점은 force-dynamic(항상 최신)을 선호하지만 사용자 관점의 2.7초 대기가 더 큰 비용 — 3분 revalidate로 절충(데이터 자체가 3시간 주기이므로 실질 손실 0). 디자인 관점의 다크모드 요구는 토큰 정비 전 착수 시 부채 2배가 되므로 Phase 3로 유예.
